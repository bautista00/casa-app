## Level-by-level detail

### L0 Static & build

| Check | Result |
|---|---|
| `npm run lint` | **FAIL** — exit 1, one error (`require()` at `src/lib/supabase/server.ts:31`) → CASA-013 |
| `npx tsc --noEmit` (cold clone) | fails on `LayoutProps` — **documented framework behaviour, not a defect** |
| `npx tsc --noEmit` (after `next build` / `next typegen`) | **PASS**, exit 0 |
| `npm run build` | **PASS** — 9.4 s, 12 routes + `ƒ Proxy (Middleware)`, no `.env.local` needed |
| Env parity `src/**` ↔ `.env.local.example` | **PASS** — 6 variables, exact match both ways |

The `tsc` point deserves a sentence, because it looks like a bug and is not. `LayoutProps<'/'>` at
`src/app/layout.tsx:32` is the idiom the Next.js 16 docs themselves use; the type is generated into
`.next/types` by `next dev`, `next build` or `next typegen`
(`node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/layout.md:109`). On a cold
CI checkout `tsc` therefore fails until typegen runs. That is a missing npm script, not a code defect
— see Observations. `src/proxy.ts` is likewise correct: Next.js 16 renamed `middleware` to `proxy`
(`.../upgrading/version-16.md:614`), and the build output confirms it is being picked up.

### L1 Unit (domain logic)

`npm test` — 2 files, 18 tests, all green. Then the boundaries those 18 tests do not reach were
attacked directly with throwaway probes; every number quoted in this report and in `qa/BUGS.md` is
real output, saved under `qa/reports/2026-09-14/L1-probe-*.txt`.

**Ranking — clean.** Eleven tie configurations were executed: full 4-way tie, top-only tie,
bottom-only tie, all-zero household, 2-member, 1-member, empty household, middle tie, and the
points-tie-broken-by-task-count case. Competition ranking is correct for 5,5,3,3 → 1,1,3,3;
5,3,3,1 → 1,2,2,4; 5,5,5,1 → 1,1,1,4. Winner/last-place suppression on ties behaves exactly as the
doc comment promises, and points credited to a member who has left the household are silently
dropped rather than crashing. **No defects.**

**Recurrence — clean.** Month-end clamping is correct (31st → Feb 28 → Mar 31; 29th → Feb 29 in 2024,
Feb 28 in 2026), no duplicates in any configuration, weekly with an empty or invalid day set returns
`[]`, and the daily horizon is inclusive at both ends (15 dates for `horizon = 14`). One result looks
alarming and is not: a monthly occurrence more than 14 days away returns `[]`, which is correct for a
rolling horizon — it enters the window in time as long as the generator runs at least every 14 days.
Recorded as TC-DOM-019 so nobody re-files it. **No defects.**

**Week — broken, and completely untested.** `src/lib/domain/week.ts` has no test file at all. Walking
`getWeekWindow` across a full week for `weekEndDay = 0` and `= 1` shows the window running *from* the
chosen day rather than *to* it: with "la semana cierra el domingo", the window is Sun 00:00 → Sat
23:59, Sunday is excluded from the week it is supposed to close, and `daysRemaining` reads 7 on the
closing day instead of 1. The function's own doc comment says the opposite. → **CASA-004**, with a
ready-to-paste `week.test.ts` in the bug entry.

Argentina has had **no DST since 2009**, so no DST case was filed — the risk register's R1 concern is
real, but the actual failure is a plain day-index error, not a clock shift.

### L2 Contract & integration

**Signatures vs `CONTRACT.md`: no drift.** All 24 data functions, all 10 domain exports and all 14
type exports are listed, and nothing extra is exported. (TC-PERF-007.)

**Queries vs the schema: correct.** The migration was applied **verbatim** to a local PostgreSQL
16.13 instance with thin Supabase stubs (`auth.users`, `auth.uid()`, an `authenticated` role) — the
harness is checked in at `qa/reports/2026-09-14/L2-pg-harness-setup.sql` and `L2-pg-seed.sql`, seeded
to match `PRODUCT.md` §Users. Every column referenced by `src/lib/data/*` exists, and the FK alias
names the code uses are the ones Postgres actually generates. `tasks` has three FKs to `profiles`, so
the assignee join genuinely needs disambiguation — and the code does it correctly with
`profiles!tasks_assignee_id_fkey`.

**RLS reachability: three findings, one of them fatal.**
- Reading `household_members` as a normal member fails with
  `42P17 infinite recursion detected in policy` — the `"Owners can manage members"` policy queries its
  own table instead of going through the `SECURITY DEFINER` helper the migration already defines for
  exactly this reason. → **CASA-001.** The candidate fix was applied inside a transaction and all five
  previously-failing cases passed, then rolled back; the transcript is in the bug entry.
- `profiles` is `select using (true)`, so any signed-in user reads every user's name and phone.
  → **CASA-005.**
- `join_household` is `SECURITY DEFINER` and trusts a caller-supplied `user_id`, so anyone with a code
  can add anyone else to a household, and the return value leaks the household's `join_code`.
  → **CASA-009.**

What is *right*: tasks and households are properly isolated (an outsider sees zero of either), and
`weeks` / `week_scores` are read-only to members so nobody can rewrite who won.

**Constraints:** `unique nulls not distinct (template_id, due_date)` collapses to "one ad-hoc task per
date in the entire table, across every household". Proven with four inserts. → **CASA-002.** The
constraint's *intended* job — one generated instance per (template, date) — does work, and that is the
behaviour that must survive the fix.

**Call-site error handling (R6):** the three server components make 13 awaited calls to throwing data
functions with **zero** `try` blocks, and there is no `error.tsx`, `global-error.tsx` or
`not-found.tsx` anywhere. → **CASA-008.**

### L3 E2E / UI

Environment: `.env.local` copied from the example, `npm run dev`, then driven two ways —
`curl` for status/redirect behaviour and headless Chromium (Playwright installed **outside** the repo;
`package.json` untouched) at 390×844, `es-AR`, `America/Argentina/Buenos_Aires`.

Routes, signed out: `/` and all five app routes `307 → /login`; `/login` and `/callback` render 200.
No 500s, no console errors, no failed requests, no horizontal overflow at 390 px on any measured page,
Fredoka on headings and Nunito on body as the brand requires. The login form is properly labelled,
disables its button while submitting, and shows a correct Spanish error toast when Supabase is
unreachable — that path is genuinely well built.

The one signed-out failure: `/callback` renders a spinner and **nothing else**, forever. Sampled at
1 s, 5 s and 15 s: `text: ""`, spinner still turning, no console error, no way back. That is what a
family member sees when a magic link has expired or was already used. → **CASA-014.**

Everything behind auth is `BLOCKED`. Where a defect could be proven without rendering the page — a
timezone-naive expression, a missing in-flight guard, a realtime payload that cannot carry a join —
the case is marked FAIL and its Notes say the verdict came from code review plus an executed probe.
No signed-in case is marked PASS.

### L4 Cross-cutting

**i18n / voseo.** One register slip, precisely located: `es.ts:106`
`'Ej: Elige la cena del viernes'` should be "Elegí" (CASA-017). Everything else in the file is correct
Argentine voseo. Fourteen user-visible strings, across fifteen sites, bypass `es.ts` entirely (CASA-016) — the text is mostly
fine, but they are invisible to anyone proofreading the copy in one place. Day-name indexing is
correct (0 = Domingo) across all three day pickers.

**Brand.** Fredoka + Nunito confirmed in the browser; the indigo/orange palette and the 1 rem radius
scale are in place; claymorphism reads correctly on the auth screens. One note: the heading font is
opted into per element rather than applied to all headings, so `h2` renders in Nunito.

**Accessibility.** Focus rings and label bindings pass. Three failures: pinch-zoom is disabled
globally (`maximum-scale=1`, CASA-018); icon-only buttons compile to 32–40 px against a 44 px minimum
on the primary device (CASA-019); and the gamification colours fail contrast badly — white on the
winner's gold rank pill measures **1.77:1** (CASA-020). Icon-only buttons also lack accessible names
(TC-A11Y-008), folded into the same fix batch rather than filed separately.

**Security & privacy.** The service-role key is clean: it appears only in
`src/lib/supabase/server.ts`, no client component imports that module, and `createServiceClient` is
called only from the three cron routes. The cron *check itself* is not clean: with `CRON_SECRET`
unset, the template literal produces the string `"Bearer undefined"`, and sending exactly that header
returns 200 on all three routes — which then run with a service-role client that bypasses RLS
entirely. Reproduced twice. → **CASA-003.** No phone numbers or emails appear in logs or responses,
though the reminders route does return member display names in its body — harmless to Vercel's
scheduler, a leak while CASA-003 is open.

**State & data integrity.** Double-submit on the board's complete button has no guard, and because
`completeTask` uses `.eq('status','open').single()`, the second call errors and the catch block
*reverts* the card to open while the database has it done (CASA-012). Realtime updates replace the
whole task object and lose the joined assignee (CASA-015). A non-owner's settings save reports success
and writes nothing (CASA-010). A task with no due date is displayed with a points badge but is
excluded from both scorers (CASA-011).

### L5 Exploratory charters

Five charters, roughly 10 minutes each, aimed at the risk register.

**Charter 1 — Explore the schema with a real PostgreSQL instance and two seeded households, to
discover isolation gaps (R3).** The highest-yield 10 minutes of the cycle: three defects, including
CASA-001, which nothing else in the plan would have caught without live credentials. Worth
institutionalising — the harness is checked in and takes about a minute to re-run.

**Charter 2 — Explore the cron endpoints with a deliberately misconfigured environment, to discover
auth failure modes (R4).** Removing `CRON_SECRET` from `.env.local` — the shape of a real deployment
mistake — immediately produced CASA-003. Testing the *absence* of configuration found something that
testing its presence never would.

**Charter 3 — Explore the week boundary by walking every day of a week for every `week_end_day`, to
discover off-by-one errors (R1).** Produced CASA-004 and, with it, the realisation that `week.ts` has
no test file at all. Also cleared a suspicion: the dead guard at `week-close/route.ts:52` can never be
true, but it is harmless — not filed.

**Charter 4 — Explore `/login` and `/callback` in a real mobile browser, to discover dead ends a
signed-out user can reach (R7).** Produced CASA-014 and CASA-018, and confirmed the login error path
is genuinely good. Also nearly produced a false positive: measuring the focus ring immediately after
`Tab` caught it mid-`transition-all` at 1.6 % opacity, which reads as "no focus indicator". Waiting a
second showed a perfectly good 3 px ring. Recorded in TC-A11Y-004 so the next run does not repeat it.

**Charter 5 — Explore the recurrence generator's month-end and horizon behaviour, expecting duplicate
or skipped tasks (R5).** **Clean.** No duplicates, no skipped month-ends, correct leap-year handling.
The generator's real defect turned out to be somewhere else entirely — the rotation is computed once
per template instead of once per occurrence (CASA-007). A clean charter is still evidence: R5 can be
downgraded next cycle.

## Observations (not defects)

Kept out of `qa/BUGS.md` on purpose — the dev queue should contain only things that are broken.

**Unbuilt, though the scaffolding exists.** Several features have their data layer, i18n strings and
even their contract entries in place, but no screen:
- **No way to delete or edit a task.** `deleteTask`, the RLS delete policy and `es.task.delete` all
  exist; nothing calls them. A typo'd chore stays on the board forever, and a non-technical member has
  no workaround. This is the largest gap between `PRODUCT.md` §Evidence ("task CRUD") and the app.
- **No timezone control** anywhere, despite `PRODUCT.md` §Operating Context promising a configurable
  timezone, and despite `es.onboarding.timezone` / `es.settings.timezone` being defined.
- **WhatsApp is a TODO.** `src/lib/notify/whatsapp.ts` is never imported; the reminders route composes
  a message, drops it, and returns `{"message":"Reminders sent"}`. At minimum the response should not
  claim it sent anything. This is the product's only notification channel.
- **Leave household / danger zone** (`es.settings.leaveHouse`, `dangerZone`), **test message**
  (`sendTest`, `testSent`), **week recap** (`es.recap.*`), and the per-week score breakdown
  (`getWeekScores` is imported by Historial and never called) are all defined and unused.

**Design smells worth a look.**
- The leaderboard styles rows by array index (`i === 0`, `i === 1`) while printing `member.rank`, so
  the second of two tied leaders gets silver styling next to a "1".
- `es.leaderboard.noPrize` exists but the empty prize state renders nothing at all.
- Creating a recurring task shows "Tarea recurrente creada" and then an empty board until the
  generator runs — from the family's side that looks like a failure.
- The board never shows *which* task is the dreaded one; it is only visible in Ajustes.
- A past winner who has left the household renders as "🤝 Empate" in Historial, because the name is
  resolved from the *current* member list.
- The header's "Crear una casa" sends the user to `/onboarding`, which immediately redirects a user
  who already has a household back to the board — so the create-house screen may be unreachable after
  the first household. Worth 30 seconds in a browser once CASA-001 is fixed.
- `createHousehold` does two inserts without a transaction; a failure between them leaves an orphan
  household the creator cannot even see, since the SELECT policy needs the membership row.
- `join_household` raises its errors in English and the UI pattern-matches on `msg.includes('Already')`
  to translate them. It works; it is brittle, and any other failure is reported as "invalid code".
- `copyCode` awaits `navigator.clipboard.writeText` with no `try`/`catch`.
- Every `SECURITY DEFINER` function (`is_member`, `join_household`, `handle_new_user`) lacks
  `set search_path = public` — Supabase's own advisor flags this as `function_search_path_mutable`.
  Low exploitability on Supabase's default grants, but it costs one line each and the fixes for
  CASA-001/005/009 touch these functions anyway.
- The dead guard at `src/app/api/cron/week-close/route.ts:52` can never evaluate true. Harmless today,
  but it means a household created mid-week gets a closed week with no tasks on the first cron run.

**Tooling and process.**
- **Add a `typecheck` script.** `"typecheck": "next typegen && tsc --noEmit"` makes exit criterion 3
  runnable on a cold CI checkout; today `npx tsc --noEmit` fails on a fresh clone purely because route
  types have not been generated yet.
- **`eslint.config.mjs` does not ignore `.claude/**`.** Roughly 100 of the 118 lint warnings come from
  vendored skill scripts, which buries the ~18 real ones in `src/**` (unused imports in
  `board-view.tsx`, `historial/page.tsx`, `nueva/page.tsx`, `app-shell.tsx`, the cron routes). Two of
  those unused imports — `useOptimistic` and `useTransition` in `board-view.tsx` — look like an
  abandoned attempt at the very guard CASA-012 is about.
- **`src/lib/domain/week.ts` has no test file.** Three of the five S1 defects would have been caught
  cheaply by unit tests; this is the single highest-value coverage gap in the repo. A complete
  `week.test.ts` is included in CASA-004, ready to paste.
- Vitest prints `ESM syntax in a file loaded as CommonJS (vitest.config.ts)`. Harmless now; rename to
  `.mts` or set `"type": "module"` before a future Vite major turns it into an error.
- Consider `lang="es-AR"` on `<html>` for a more accurate screen-reader voice.

## Method note — where each verdict came from

Stated plainly, because a verdict without a stated method is not reproducible:

- **Executed for real:** all L0 checks; `npm test`; every L1 domain probe (outputs saved verbatim);
  the entire L2 schema, RLS, constraint and function analysis (local PostgreSQL 16.13, migration
  applied unmodified, harness and seed checked in); the cron auth matrix (curl against the dev
  server, twice); all signed-out route behaviour (curl + headless Chromium at 390×844); viewport,
  font, overflow, touch-target, focus and contrast measurements (browser, against compiled CSS).
- **Code review plus an executed probe, with live rendering blocked:** CASA-006, -008, -010, -011,
  -012, -015, -021, -022, -023. Each of these is a deterministic code path — a timezone-naive
  expression, a missing guard, a falsy check, a payload shape, a missing file — and each bug entry
  says so in its "Steps to reproduce" and "Evidence". None was inferred from behaviour nobody saw.
- **Not claimed:** no browser verdict in this report was produced without actually driving Chromium,
  and no signed-in page was marked PASS.

Evidence for everything above is in `qa/reports/2026-09-14/` — 31 files: command output, SQL
transcripts, browser measurements, the Postgres harness SQL, and eight screenshots.
