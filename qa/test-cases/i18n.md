# I18N — Argentine Spanish and voseo

`PRODUCT.md` §Capabilities: "Entirely in Argentine Spanish (voseo). No multi-language support
planned." `src/lib/i18n/es.ts` is the single source of copy — a string that bypasses it is a defect
even when the text is correct, because it silently leaves the proofreading surface.

All cases run in **E0** with grep, plus a rendered check on `/login` in E1. All verdicts came from
real execution.

### TC-I18N-001 — Every user-visible string comes from `es.ts`

| **Env** | E0 |
| **Automated** | two greps, below |

**Steps**
1. `grep -rn --include=*.tsx -E ">[A-ZÁÉÍÓÚÑ¡¿][^<>{}]{2,}<|placeholder=\"[^\"]+\"|title=\"[^\"]+\"|aria-label=\"[^\"]+\"" src/app src/components --exclude-dir=ui | grep -v "es\."`

### TC-I18N-005 — Day names and abbreviations are Spanish and correctly indexed

| | |
|---|---|
| **Priority** | P1 |
| **Type** | i18n |
| **Level** | L0 static |
| **Env** | E0 |

**Steps**
1. Read `es.days` and `es.daysShort` in `src/lib/i18n/es.ts:124-141`.
2. Check the index convention against `Household.week_end_day` (`src/types/index.ts:29`,
   "0=Sun, 1=Mon, … 6=Sat") and against `getDay()` in the domain layer.
3. Check the consumers: the day pickers in onboarding, nueva and ajustes.

**Expected result**
Index 0 = Domingo everywhere, so the button the user taps matches the day the system stores.

**Last run** — RUN-2026-09-14 · **Verdict:** PASS · **Bug:** —
**Notes** `0: 'Domingo' / 'Dom'` … `6: 'Sábado' / 'Sáb'`, with accents. All three pickers iterate
`[0..6]` and index the same map, and `getDay()` uses the same convention. The mapping is right — what
is wrong is what the chosen day *means* for the week window (CASA-004), which is a domain bug, not an
i18n one.

Flagged as an Observation.
